**Следующий шаг:** Открыть Learning и убедиться, что словацкие фразы перегенерировались через `aicards-phrase` и подпись показывает `gemini-3.6-flash`.

## Что это

Приложение карточек для изучения языков: backend на Python, frontend на React/Vite, PostgreSQL и Docker Compose.

В Learning есть режим **Phrases**: вместо голого слова карточка показывает
короткую AI-фразу и её русский перевод с подсветкой изучаемого слова.

## Phrase mode (Learning)

- Кнопка `Phrases ON/OFF` рядом с выбором языка; выбор хранится в `localStorage`.
- Фразы генерируются в фоне через OmniRoute (с существующим Groq-fallback) и
  кэшируются в таблице `card_phrases`.
- Рабочая модель — комбо `aicards-phrase` в локальном OmniRoute: сначала
  `gemini/gemini-3.6-flash`, затем `nvidia/nvidia/nemotron-3-ultra-550b-a55b`
  и `bluesminds/nvidia/nemotron-3-ultra-550b-a55b` (strategy `priority`).
  Модель и base URL хранятся в БД (`omnirouter.chat_model`,
  `omnirouter.base_url`) и переопределяют `.env`.
- Одна фраза на карточку, общая для прямого и обратного направления.
- Карточка, которая уже является фразой/предложением, не повторяется дословно:
  модель заменяет обобщённое слово конкретным (`Nefunguje mi to.` →
  `Nefunguje mi počítač.`), а грамматически чувствительные конструкции
  (`To je presne ono.`, `Podarilo sa mi to.`) оставляет целиком и добавляет
  контекст.
- Если переигровка не прошла валидацию, retry возвращает исходную фразу
  целиком; карточка не остаётся без фразы.
- Пока фразы нет, показывается слово. Готовая фраза подменяет текст без
  перезагрузки, без сброса таймера и без изменения очереди.
- Под карточкой с фразой подписано, какая модель её сгенерировала
  (`model (phrase): ...`, включая сработавший fallback).
- Emergency не затронут: там нет ни кнопки, ни фраз.
- Прогресс `Item N of M`, порядок карточек и FSRS не меняются.
- Спека: `docs/specs/phrase-mode.md`. Решения: `docs/decisions.md`.

## Отзывчивость оценок

- Кнопки `1–4` сразу переводят на следующую карточку; запрос `/reviews`
  сохраняется в фоне. Раньше интерфейс ждал ответа сервера, и награда
  выглядела как микро-фриз.
- Ошибка сохранения показывается плашкой, а не оставляет карточку «зависшей».

## Устойчивость к зависаниям

- Проверка токена вынесена из event loop в threadpool и кэшируется на 30 с
  (logout сбрасывает кэш сразу).
- Пул подключений к удалённой PostgreSQL: `pool_pre_ping`, `pool_recycle`,
  таймауты соединения/запроса — «протухшее» соединение больше не вешает API.
- Очередь и поиск считают отзывы одним grouped-запросом вместо N+1; теги
  читаются без гидратации всех карточек.
- Frontend: таймауты запросов, защита от гонок при смене языка, ошибка с
  `Retry` вместо вечного `Loading...`.

## Единый дизайн

Правила и план перехода на семантические токены и общие компоненты —
`docs/design-consistency.md`. Коротко: цвет только через `var(--token)`,
интерактив — через `components/ui`, сырые hex запрещены линтом
(`npm run lint:design`, появляется вместе с внедрением).

## Запуск


## Где что лежит

- `backend/` — API, модели, миграции Alembic, тесты.
- `frontend/` — интерфейс на React/Vite.
- `docker-compose.yml`, `init.sql` — инфраструктура и база.
- `docs/` — спеки и решения.
- `docs/design-consistency.md` — исследование и план единого дизайна.
- `scripts/` — вспомогательные скрипты.
- `dialogs/` — итоги сессий.

## Ключевые файлы

- `docker-compose.yml` — запуск всего стека.
- `backend/app/` — основной код API.
- `backend/app/services/phrase_service.py` — фоновый генератор фраз.
- `backend/app/routers/phrases.py` — API режима Phrases.
- `frontend/src/` — основной код интерфейса.
